# 生成式推荐中的强化学习

一份面向工业商业化推荐场景的中文文献清单：**用强化学习优化生成式推荐系统**。
收录范围围绕三件事——生成式推荐器如何用 RL / 偏好优化训练、如何设计驱动它的 Reward 系统、
以及如何在实时在线学习的约束下完成 On-Policy 演进，并对齐 eCPM / GMV 等商业化目标。

过去十余年，工业推荐系统的主干始终是判别式的：召回、粗排、精排、重排逐级筛选，每一级为候选逐个打分，最终展示结果由分数排序拼装而成。这一范式便于工程解耦，却把物品语义、上下文与列表整体结构切散在多个模型之间，各级目标也难以一致。以语义 ID 与序列建模为基础的生成式推荐改变了这一格局：模型不再对候选逐个评分，而是把用户历史当作前缀，直接自回归地生成一份推荐结果——从单个物品的标识符，到整版列表乃至整页布局。检索、排序与重排被收进同一个骨干，级联带来的信息损失与目标错位随之减少。

然而生成式骨干本身只学会了复现日志中出现过的行为。要让它朝着"更好的推荐结果"持续演进，训练信号就必须来自结果的优劣而非词元的似然，这正是强化学习与偏好优化进入的位置：DPO 一系用成对或列表级偏好塑形生成分布，GRPO 一系以组内相对优势替代价值网络，把点击、转化、停留时长等结果指标直接写进目标函数。随之而来的是一整套新问题。奖励定义在列表或会话层级，梯度却要落到每个词元，信用分配因此成为瓶颈；有效反馈稀疏且高度偏置；奖励模型一旦被过度优化，就会出现推荐幻觉、流行度放大与各种形式的 reward hacking。奖励建模、过程监督与稳健化训练由此成为与骨干设计同等重要的研究对象。

落到商业化推荐与广告，这些问题被实时性进一步放大。线上系统是持续学习的：内容、用户与竞争环境每天都在变化，模型需要在小时甚至分钟级完成更新，这要求一套可实时归因的 Reward 系统，把点击、转化、成交与体验信号及时回流，并支撑尽可能贴近 on-policy 的演进机制；离线日志训练出的策略与线上分布之间的偏差，往往在数次迭代内就被放大。探索同样是有代价的：每一次试探都消耗真实流量与广告主预算，安全探索与部署效率并非可选项。优化目标本身也是多维的——eCPM 与 GMV 需要与生成式竞价、拍卖机制保持激励自洽，又必须与用户体验、留存和生态健康相互平衡。本清单沿这条工业主线组织，收录那些让推荐结果被直接生成、用强化学习驱动其持续演进、并在真实商业目标下被评估的工作。

## 收录标准

一篇论文进入**核心**收录，需要同时满足：

1. **推荐器是生成式的**：自回归或非自回归地生成物品标识符、语义 ID、整条列表 / slate、整页布局或 query，而不只是对候选逐个打分；
2. **训练信号来自 RL 或偏好优化**：policy gradient / REINFORCE、PPO、GRPO 及其变体、actor-critic、RLVR、DPO / SimPO / ORPO 等，或者构建了驱动这类优化的显式 Reward Model。

以下三类即使不完全满足第 1 条，也按核心收录，因为它们正是工业落地的关键环节：**Reward 系统本身**的设计与稳健化；
**实时 / On-Policy 更新与探索**机制；**生成式竞价与拍卖**及 eCPM / GMV / LTV 等商业化目标的 RL 优化。

**相邻**收录用于支撑主线但自身不含 RL 的生成式骨干、以及提供长期价值与奖励机制的经典 RL4Rec 工作，数量刻意控制。

## 主线梳理

### 1. 从判别式级联到生成式推荐

传统推荐以逐个打分再排序的方式组织级联，物品语义与列表结构被拆散在多个阶段。TIGER (2023) 用语义 ID 把检索改写为序列生成，OnePiece (2025) 考察统一骨干的规模化规律，MERGE (2026) 处理流式场景下的物品索引更新，OGR (2026) 把排序与整版列表收进同一模型，UniROM (2025) 则以单一生成模型替代广告级联栈。GenRec Survey (2025) 对这一范式转移做了系统梳理。

### 2. 强化学习与偏好优化作为训练信号

监督微调只能复现日志行为，难以表达整份结果好在哪里，偏好优化与策略梯度因而成为主训练信号。S-DPO (2024) 引入多负例，Align^3GR (2026) 做多层偏好对齐，RankGR (2026) 用列表级 DPO 训练淘宝生成式检索；GRPO 以组内相对优势替代价值网络，F-GRPO (2026) 统一整版生成与排序。信用分配是核心难题：SAPO (2026) 做步骤对齐的优势估计，DeGRe (2026) 提供步级稠密监督。

### 3. 奖励系统设计与 reward hacking

奖励定义决定生成器实际学到什么。GoalRank (2026) 用列表级奖励模型蒸馏出仅含生成器的排序器，NLGR (2025) 用邻居列表传递评估器的相对奖励，PROMISE (2026) 以过程奖励支撑测试时扩展。工业系统更依赖复合奖励：RecGPT-V2 (2025) 在受限多奖励下引入判官式评估。抗噪与防套利同样关键：AdaGRPO (2026) 自适应平衡损失，RosePO (2024) 抑制幻觉与流行度偏置。

### 4. 实时更新、On-Policy 演进与探索

商业化推荐是持续在线学习的系统，策略与流量每日漂移。Top-K REINFORCE (2019) 的 off-policy 修正是从日志学习的基线，SORL (2022) 则直面线上广告系统做安全在线 RL。近期工作把更新压到会话与请求级：OneRec-V2 (2025) 在真实反馈上做时长感知奖励塑形，SPRec (2025) 以自博弈实现 on-policy DPO；探索代价须受控，DEGR (2026) 做探索驱动的生成式重排。

### 5. 商业化目标、生成式竞价与拍卖

广告场景以 eCPM/GMV 为目标，须与拍卖机制自洽。GR4AD (2026) 与 GPR (2025) 分别在快手与腾讯把广告栈压成单一生成模型，EGA-V2 (2025) 引入排列感知奖励与可微拍卖，OneLoc (2025) 以 GMV 为奖励。竞价侧 AIGB-R1 (2026) 用解耦 GRPO 让生成式出价自我演进，GUIDE (2026) 提供价值引导探索；机制侧 NGA (2025) 研究带外部性的生成式拍卖。

### 6. 评测、模拟器与世界模型

线上试错代价高，离线可信度是瓶颈。RecoGym (2018) 与 RecSim (2019) 奠定可配置仿真环境，KuaiSim (2023) 面向列表与留存模拟，RL4RS (2023) 给出真实日志基准。LLM 时代更重用户侧保真：Agent4Rec (2024) 让智能体扮演用户，UserMirrorer (2026) 用真实反馈对齐轻量模拟器；评判侧 LLM-Judge Top-K (2026) 把评委纳入离线评测。

## 不收录的内容

- 纯 CTR/CVR 预估、特征交互与判别式排序模型：若既不生成推荐结果，也不含强化学习或奖励模型成分，则不属于本清单，相关工作见 README_ALIBABA.md。
- 不含生成成分的 slate/整页推荐研究：列表级 off-policy 评估与学习、点击模型、cascade bandit 等，均由 README_SLATE.md 收录。
- 多阶段推荐链路中跨阶段的 off-policy 学习与评估：召回与排序耦合的重要性加权、级联倾向性建模、流水线级离线策略选择等，归 README_TWOSTAGE.md。
- 只做 prompting、指令微调或蒸馏的 LLM 推荐工作：若全程不涉及强化学习、偏好优化或奖励模型，即使使用生成式骨干也不收录。
- 与推荐、广告场景无关的通用 LLM 强化学习：数学推理、代码生成、通用对齐等方向的 GRPO/DPO/RLVR 方法本身不单列，仅在被本清单内工作直接引用时作为方法背景提及。

## 补充说明

- 每条目均由实时检索发现，并通过抓取 arXiv / DOI 页面核实标题、年份、发表信息与「是否真的使用 RL 或 Reward Model」，再经一轮对抗式范围复核；未能核实的候选已剔除。
- 中文摘要中的线上指标（CTR、GMV、eCPM、观看时长等）均来自论文自述，未做独立验证。
- 作者单位仅在论文页面明确列出时才写入；页面未列出的一律留空，不做推断。

## 后续补充建议

新增条目建议包含：

- 生成对象是什么：物品标识符、语义 ID、整条列表、整页、query 还是出价策略；
- 训练信号是什么：PPO / GRPO / DPO / REINFORCE / RLVR，以及 reward 从哪里来（人工规则、排序模型、reward model、线上真实反馈）；
- 更新方式：离线后训练、准实时、还是真正的在线 on-policy；是否讨论了探索机制；
- 优化目标与线上结果：是否对齐 eCPM / GMV / LTV，是否有 A/B 数据；
- 论文、代码、数据集与 BibTeX 链接。
